# 볼트 리서치 교차검토 글쓰기 (v2)

볼트에서 글을 쓸 때 **03-Researcher를 원천으로 참조**하고, 비교검토를 함께 제시해
**02-Writing/준비 폴더**에 올립니다. 리서처가 보강되면 파생 참조본을 갱신하는
**유지보수 절차**까지 포함합니다.

이 스킬은 글을 "리서치에 근거한 글"로 만드는 것이 목적이며, 사용자 고유의 문체를
바꾸는 것은 목적이 아닙니다.

## 2계층 구조 (핵심 개념)

```
03-Researcher/          ← 원천 (Single Source of Truth) — 사실·출처·인용
   └ 철인-리서치/            여기만 보강한다. 나머지는 여기서 파생된다.
02-Writing/철인/        ← 파생 참조본 — 요약·대조표 (리서처에서 파생)
02-Writing/준비/        ← 검토 대기 초안
```

- **원천에만 새 사실을 추가**합니다. 파생본은 원천에서 다시 만들어 냅니다.
- 파생본과 원천이 어긋나면 **원천이 이깁니다.**

## When to Use

- 글봇이 글(에세이·주저리·기고문·칼럼)을 써 달라는 요청을 받았을 때 → **절차 A**
- 리서처(`03-Researcher/`)가 보강되었거나 보강이 필요할 때 → **절차 B**
- 기존 초안을 리서치 자료와 대조해 검토할 때 → **절차 A** (4단계부터)

**Don't use for:** 일기(→ `02-Writing/일기장/`), 단순 맞춤법 교정, 리서치 자체 수행(→ 절차 B).

## 절차 A — 글쓰기 (매 요청)

0. **(선택) 페르소나 지정** — 사용자가 "버크의 목소리로", "콩도르세처럼" 등 철인을 지정하면
   `02-Writing/철인/페르소나/<이름>.md` 를 `read_file`로 읽고 그 **말투·개념·금기**를 따릅니다.
   - 완료 기준: 페르소나 파일을 읽었고, **금기 목록**을 확인했음.
   - 페르소나 파일이 없으면 새로 만들지 말고 사용자에게 알립니다.
   - **주의:** 페르소나는 봇을 늘리지 않기 위한 장치입니다. 철인마다 봇을 만들지 않습니다.

1. **주제·글 종류 확인** — 무엇을, 어떤 문체로 쓸지 확정합니다.
   완료 기준: 주제 한 문장 + 글 종류(에세이/주저리/기고) 확정.

2. **리서치 검색** — `search_files`로 두 볼트의 `03-Researcher/`를 차례로 확인합니다.
   `search_files(pattern="버크", path="<원천볼트>/03-Researcher", output_mode="files_only")`
   - 완료 기준: 인용할 자료 **1개 이상** 확보.
   - 원천이 비었을 때만 파생 참조본(`02-Writing/철인/`)으로 대체하고, 그 사실을 글머리에
     `리서치 원천 없음 — 파생 참조본으로 대체` 로 명시합니다. **지어내지 않습니다.**

3. **비교검토 작성** — 자료와 글의 주장을 4항목으로 대조합니다.
   - **일치** — 리서치가 뒷받침하는 지점
   - **긴장** — 어긋나거나 반대되는 지점
   - **보완** — 리서치가 더해주는 새 관점
   - **출처** — 각 인용의 정확한 출처
   완료 기준: 4항목 모두 채워지고, 각 항목에 근거 문서 경로가 붙음.

4. **준비 폴더에 저장** — `write_file`로 `02-Writing/준비/YYYY-MM-DD-제목.md`에 저장합니다.
   - 같은 이름이 있으면 `-01`, `-02` … 첫 빈 번호를 붙입니다.
   - 첫 줄 `상태: 검토대기`, 끝에 `## 출처` **필수**. 템플릿: `templates/글-템플릿.md`
   완료 기준: 파일 저장 + 첫 줄과 출처 항목 존재.

5. **한 줄 보고** — `✅ 02-Writing/준비/<파일명> 에 저장했습니다. (검토 대기)`
   완료 기준: 사용자가 위치를 알 수 있음. **글 전문을 채팅에 붙이지 않습니다.**

6. **승인 대기** — 사용자가 "검토 끝/승인"을 말할 때까지 이동 금지.
   승인 시 원래 폴더로 옮기고 첫 줄을 `상태: 승인`으로 바꿉니다.

## 절차 B — 리서처 보강 (정기 · 변화 감지 시)

1. **변화 감지** — `terminal(command="bash <skill_dir>/scripts/research-watch.sh")`.
   스크립트가 리서처 파일 해시를 비교해 **변경·신규·삭제 파일 목록**을 출력합니다.
   완료 기준: 변경분 목록 확보 (없으면 "변경 없음"으로 종료).

2. **변경 내용 확인** — 변경된 파일을 `read_file`로 읽어 무엇이 추가·수정됐는지 파악합니다.
   완료 기준: 바뀐 사실을 한 문장으로 요약.

3. **파생본 갱신 판단** — 변경분이 아래에 해당하면 파생본을 갱신합니다.
   - 새 철인 추가 → `철인-리스트` 행 추가
   - 개념·계보 변화 → `개념-계보` 수정
   - 진영 논점 변화 → `보수-진보-비교` 표 수정
   완료 기준: 갱신 대상 파일을 명시적으로 결정 (없으면 "갱신 불필요"로 기록).

4. **파생본 갱신** — `patch`로 해당 부분만 고칩니다. 원천의 출처 표기를 함께 옮깁니다.
   완료 기준: 파생본이 원천과 어긋나지 않음.

5. **보강 로그 기록** — `03-Researcher/철인-리서치/보강-로그.md` 에 날짜·변경·갱신 내용을
   추가합니다. 템플릿: `templates/보강-로그-템플릿.md`
   완료 기준: 로그 항목 1개 추가.

## Quick Reference

```
# 리서처 변화 감지
terminal(command="bash <skill_dir>/scripts/research-watch.sh")

# 리서치 검색
search_files(pattern="<키워드>", path="<볼트>/03-Researcher", output_mode="files_only")

# 파생본 갱신 (부분 수정)
patch(mode="replace", path="<볼트>/02-Writing/철인/철인-리스트.md", old_string=..., new_string=...)
```

## 규칙 (볼트 Skill.md — 최우선)

- **출처 명기 필수.** `## 출처` 없는 문서는 만들지 않습니다.
- 출처를 찾을 수 없으면 첫머리에 `> 출처: 없음`을 명기하고 사용자에게 알립니다.
- 직접 지은 문장은 `창작`, 요약·구성은 `편집물`, 미검증 인용은 `원문 대조 필요`로 표기합니다.
- 사용자 문체 존중 — 의미를 바꾸는 재작성을 하지 않습니다.
- 파생본을 고칠 때 **원천을 먼저 확인**합니다. 원천에 없는 내용을 파생본에 넣지 않습니다.

## Pitfalls

- **리서치를 지어내지 마세요.** 원천에 없으면 "없음"이 정답입니다.
- **파생본을 원천처럼 쓰지 마세요.** 새 사실은 원천에 먼저 넣습니다.
- **준비 폴더를 건너뛰지 마세요.** 초안은 항상 준비 폴더를 거칩니다.
- **사용자 승인 없이 이동 금지** (Skill.md 7항).
- vault `03-Researcher` 는 root 소유일 수 있습니다 → workspace 볼트로 우회하고 사용자에게 알립니다.
- 보강 로그를 빠뜨리면 "무엇이 언제 바뀌었는지" 추적이 끊깁니다.
