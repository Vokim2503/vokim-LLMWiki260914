# 시스템 구조 — 현재 만들어져 있는 것 전체 지도

> **출처: 없음** — 볼트 내부 구조 설명 문서 (외부 출처 없음).
> 근거: 실제 실행·설정 결과 캡처 (2026-09-16). 각 파일의 출처는 개별 문서에 명시되어 있습니다.
> **용도:** 사용자 검토용 — 현재 구조가 어떻게 만들어졌는지 한눈에 보는 지도.

## 1. 한눈에 보는 전체 그림

```
                    ┌─────────────────────────────────────┐
                    │        GitHub 저장소 (원격)          │
                    │   Vokim2503/vokim-LLMWiki260914     │
                    └──────────────┬──────────────────────┘
                                   │ git pull / push (10분 크론)
                    ┌──────────────▼──────────────────────┐
                    │  workspace/ (git 클론, hermes 소유)  │  ← 진실의 원본
                    │  = GitHub과 1:1 미러                │
                    └──────────────┬──────────────────────┘
                                   │ 양방향 복사 (자기치유 스크립트)
                    ┌──────────────▼──────────────────────┐
                    │  obsidian-sync/ (라이브 보관함)      │  ← 글봇이 읽고 씀
                    │  = 사용자 옵시디언 미러              │
                    └─────────────────────────────────────┘

  봇 (데스크톱 Bots 탭)
   ├── 헤르메스 (default)  — 이 대화
   └── 글봇 (writing)      — 글쓰기 전용 · 페르소나 기능
```

**핵심 규칙:** GitHub = workspace = obsidian-sync **세 곳이 같은 내용**이어야 합니다.
동기화 스크립트가 매 실행마다 이를 유지하고, 어긋나면 자동 고칩니다.

## 3. 봇 구조 — 왜 2개뿐인가

```
데스크톱 Bots 탭 = 프로필 목록 = 2개
├── 헤르메스 (default)   — 관리자 역할
└── 글봇 (writing)      — 글쓰기 전용

철인 목소리 = 페르소나 파일 (봇이 아님)
└── 글봇이 "버크의 목소리로"라는 말을 들으면
    페르소나/버크.md를 읽고 그 말투·개념·금기로 글을 씀
```

**왜 이렇게 했나:**
- 봇 1개 = 프로필 1개 = 게이트웨이 프로세스 1개 (서버 자원 사용)
- 철인 44명을 전부 봇으로 만들면 서버 부담 + 목록 혼란
- 페르소나 파일은 파일 추가만으로 44명까지 확장 가능 (봇 비용 없음)

## 4. 2계층 구조 — 리서처 ↔ 글쓰기

```
03-Researcher/철인-리서치/     ← 원천 (사실·출처·인용)
   └ 새 사실은 여기에만 추가
          ↓ (파생)
02-Writing/철인/               ← 파생 참조본 (요약·대조표·페르소나)
   └ 원천에서 다시 만들어 냄
```

**규칙:** 원천과 파생본이 어긋나면 **원천이 이깁니다.** 리서처가 보강되면
`research-watch.sh`가 변화를 감지하고, 파생본 갱신을 판단·기록합니다 (보강-로그).

## 5. 동기화 구조 (자기치유 v2)

```
[10분 크론] → obsidian-sync.sh v2
  0. 자기치유   : root 소유 잔재 자동 정리 (내용 보존)
  1. git pull   : 사용자 Mac/iPad 변경 수신
  2. workspace→vault : GitHub 변경을 라이브 보관함에 반영
  3. 일지 이동  : 볼트 루트의 날짜 파일 → 일기장 (중복 시 -01, -02)
  4. vault→workspace : 글봇이 쓴 것 수집
  5. commit+push : GitHub로 송신 (실패 시 1회 재시도)
  6. 누락 검증  : 양쪽 파일 비교, 누락을 로그로 보고
```

**이전 문제 → 해결:**
- root 소유 잔재로 동기화가 막히던 것 → 매 실행 자동 청소
- 한글 경로 오판으로 누락 61건 오보 → `core.quotepath=false` 수정
- 크론이 1회성으로 죽어 있던 것 → 무한 반복 복구

## 6. 글쓰기 절차 (스킬: vault-research-crossreview)

글봇이 글을 쓸 때 **항상** 이 순서:

```
1. (철인 지정 시) 페르소나 파일 읽기 — 말투·개념·금기 확인
2. 리서처 검색 (vault → workspace 순)
3. 비교검토 작성 — 일치 · 긴장 · 보완 · 출처 (4항목)
4. 02-Writing/준비/에 저장 — 첫 줄: 상태: 검토대기
5. 한 줄 보고 — 저장 경로만
6. 승인 전 이동 금지
```

## 7. 자동화 목록

| 자동화 | 내용 | 주기 |
|---|---|---|
| 일기장 자동 저장 | 달력 아이콘 파일 → `02-Writing/일기장/` (+ -01/-02 번호) | 10분 |
| 볼트 동기화 | GitHub ↔ workspace ↔ vault 양방향 + 자기치유 | 10분 |
| 리서처 감시 | `research-watch.sh` 해시 비교 → 변경 감지 | 수동/요청 시 |
| 글봇 게이트웨이 | `hermes -p writing gateway run` (수동 유지 — root s6 슬롯 문제) | 재부팅 후 재실행 필요 |

## 8. 운영 규칙 (Skill.md 9원칙 요약)

1. 폴더별 특성 지정 · 2. 일임 완수 · 3. 할일/금지 구분 · 4. 편안·정중한 언어
5. 쉽고 감명 깊은 문체 · 6. 철인·논문 참조 · 7. 준비 폴더 검토 후 이동
8. **출처 명기 최우선** (출처 없으면 `출처: 없음` 명기, 없으면 문서 생성 금지)
9. 자유로운 글감 장려
